- Sequential ablation, sharper strawman (`alloc/sequential.py`, `mode="maximal"`): stage 1 gives every agent the **highest-utility** row its error headroom allows, with no sight of the frame budget; stage 2 claws time back by repeatedly applying the downgrade with the smallest utility loss per unit of time saved, then runs the same greedy fill. This is the opponent `mode="cheapest"` was not, because its error-side commitment is the one stage 2 has to live with. **It also produces the joint solver's exact assignment** - 108 feasible cells (seeds 0-5, N in {120, 300}, with and without a headroom mask, budget 0.15-0.9 of T(0)), 0 differing assignments, 0.0000% utility gap. The null survives unstructured random tables with dominated rows (m = 12 and 40, 317 further cells, 0 differences).
- What the ablation *did* localise: **the greedy fill, not the joint relaxation, is what makes the allocation exact.** Disable `fill` on all three solves and they separate immediately - cheapest-first collapses (up to 85% utility gap, it never spends the time budget at all) while maximal-first draws level with the joint Lagrangian or goes **slightly ahead of it** (up to 0.22% at small N, 0.08% at N=120), because the bisection stops at a bracket end strictly below the budget and leaves the integrality gap unspent. Re-enable the fill and all three collapse onto one assignment. So the joint Lagrangian's contribution is **speed** (O(log(1/tol) . n . m) against the two-stage O(n^2 . m)), and the exactness is the fill's. `tests/test_alloc.py` pins all of this (46 tests in that module, 98 in `tests/` under `.venv`).

Unity spreads `IJobParallelFor` over the worker threads, so the editor figure should be roughly a seventh of these (N=1200 ~1 ms), and Burst would cut it again. That sets the live demo's comfortable range at 1-3k agents without Burst.

## DECISIONS
- Repo root is `cgvr/`; `sim/`, `bench/`, `tests/` sit at root.
- Tier index: 0=HIGH, 1=MED, 2=LOW, 3=OFF.
- One significance scalar per agent: 3D distance to camera, multiplied by 2.0 when out of view (after visibility hysteresis). Visual and sim tiers each apply their own band table, hysteresis state, and per-level caps to that scalar. Visual is forced OFF when out of view; sim is not.
- Distance hysteresis is 10% on band edges. Visibility hysteresis is a 15-frame hold after leaving the frustum. Caps demote lowest-significance agents first; hysteresis state stores the pre-cap tier.
- Tiers are recorded only. Motion is full-rate reference dynamics (goal-seek plus O(N^2) chunked separation, no ORCA) for every agent regardless of tier.
- Log holds integer histograms only (no floats), so byte-identity is exact. Fixed dt 1/30, single `default_rng(seed)`.
- Phase 2 heads: behaviour head = preferred-velocity modifier (3) + gaze target (3); animation head = gesture blend weights (8, softmax) + gait parameters (5). All decode from one 16-dim latent. Training loss is the equal-weight sum of embedding reconstruction and the four per-group variance-normalised MSEs.
- Phase 2 targets are synthetic: seeded random loadings per categorical field, one intent x social interaction, tanh squashing, plus noise 0.05. The corpus has no real behaviour or animation ground truth, so the gate tests whether the latent degrades gracefully under truncation. It does not test that real behaviour decodes from text.
- Phase 2 gate criteria were fixed before running: monotone within 1e-3 at every k from 16 to 4, and no single step above 35% of the total rise. Not retuned after the 3-seed result; the 10-seed rerun used the same criteria plus a pre-set accept rule (see DONE).
- Hub queue is a scripted service window (front agent released every 45 frames, queuers rejoin at the tail). Corridor door is a hard clamp on a 1.6 m gap at x=30.

- Phase 3 cost model: `frame_ms = theta_core * N + sum theta[axis,tier<3] * n[axis,tier]`. Tier 3 of each axis is the zero-cost reference so the fit is identifiable; `theta_core` absorbs the invariant-core fixed cost plus lowest-tier costs. RLS recursion is unclamped (clamping inside the recursion diverged); costs read out are clamped >= 0. P-trace cap at 1e4 per feature guards against blow-up under forgetting.
- Allocator: rows sorted (cost asc, quality desc) so argmax tie-break prefers the cheaper row. lambda_lo = 0, lambda_hi = max U / min positive cost gap (every agent at min cost). Stop when hi-lo <= 1e-4 hi or budget slack <= 1e-3 budget, max 64 steps. Returned assignment is always the evaluated feasible end `hi`, then greedy fill by utility-gain/cost ratio while upgrades fit. If min-cost assignment exceeds the budget, return it with `infeasible=True`; never violate the error headroom mask.
- Config quality q(c) = unweighted mean of four per-axis fidelities in [0,1]. Error rate e(c) = behaviour nMSE + navigation deviation (visual axes contribute zero divergence). Couplings: impostor geometry excludes IK animation; field/core navigation excludes gesture-bearing behaviour (latent16, latent8). Dominance pruning is a runtime helper (`prune_dominated`), not applied by default.
- Oracle: brute force validates the DP at N=6 (5-row subtables); the DP is the N=200 oracle. Tests quantise costs to integer ticks and hand the same quantised costs to both solvers, so the comparison is exact.

- Phase 4 tie-break: parallel versions scan the unsorted table with an explicit comparator (score desc, cost asc, quality desc, index asc); this equals first-argmax over the serial's lexsorted rows, so the per-frame sort is gone and the fixed table can sit in constant memory.
- FMA contraction breaks bit-identity of score = (s*q) - (lam*c). NVVM contracts by default and numba exposes no flag, so real-hardware CUDA uses libdevice `dmul_rn`/`dadd_rn` (never contracted); the simulator uses plain ops. C builds use `-ffp-contract=off` (clang) / `-Mnofma` (nvc). Numba CPU does not contract without fastmath.
- Aggregate cost: threaded sums `c[a]` with numpy in agent order, the oracle's own order, so it matches for float costs too. CUDA sums per-block partials in fixed order (deterministic run to run) but not in numpy's order; with integer-tick costs the sum is exact, with float costs a last-bit difference could flip a knife-edge bisection decision. Acceptance is on ticks plus float instances that happened to agree.
- Numba binds `cuda.const.array_like` at compile time, so only quality and err (fixed) go in constant memory; the per-frame RLS cost vector is staged into shared memory by each block (1.4 KB). A CUDA-C port would `cudaMemcpyToSymbol` it. Kernels are compiled per table via a closure factory.
- CUDA host loop: launch 8 kernels, read the done flag (one 64 B D2H), repeat; early-exit launches cost a few us each. A cooperative-groups persistent kernel would remove even that but cannot run under the simulator, so it was not written.
- Occupancy statement for `k_eval` on T4 (sm_75, 40 SMs, 64 KB shared/SM, 64K regs/SM, 32 warps/SM, 16 blocks/SM, 64 KB constant): TPB 256 = 8 warps; static shared 4.1 KB (eval) / 6.1 KB (fill) per block, so shared allows 15 blocks/SM; constant 4 KB of 64 KB; threads allow 4 blocks/SM. Registers decide: <= 64 regs/thread gives 4 blocks = 32/32 warps (100%), 65-80 regs gives 3 blocks (75%). `occupancy_report(alloc)` prints regs/thread and the driver's active-blocks figure on hardware. fp64 runs at 1/32 rate on Turing: the inner loop is 2 mul + 1 sub + compare per (agent, row), ~54M fp64 ops at N=100k, of order 0.2 ms per evaluation, so per-launch overhead and the ~15 launches per frame matter more than ALU.
- Greedy fill is inherently sequential (one global argmax per step). Each step is a full N x m pass in every implementation; at N=10k the benchmark instance took 18 fill steps, more than the 13 Lagrangian evaluations. Kept for oracle identity; a capped or parallel-batch fill is a phase 5/8 decision.
- Threaded uses numba `prange` rather than Python threads; `threads=k` sets `numba.set_num_threads`. Numba could not analyse a reduction on a variable assigned in the inner loop, hence the array write plus host sum.
- `tests/conftest.py` and `alloc/cuda/__init__.py` set `NUMBA_ENABLE_CUDASIM=1` when no `nvidia-smi` is on PATH (or on macOS). On the T4 leave it unset. `numba` was installed (phase spec names Numba-CUDA); no other dependency added.

- Phase 5 WEE without Nsight: the kernel's control flow is a deterministic function of its inputs, so the counters Nsight would read (thread_inst_executed / inst_executed) are reproduced two ways: the instrumented kernel writes per-lane neighbour-loop trip counts and per-warp (max trips, sum trips, class-body mask, tier-body mask) from shared memory; the host computes the same from the sort order and the grid (Kofler et al. cost model). Static instruction weights per region (`W_FIXED/W_GATHER/W_ENTRY/W_TRIP`) turn counters into issued and executed instructions. A warp issues the gather loop max(trips) times and every distinct body its lanes need. The test asserts the counters agree; the sweep raises if they differ on hardware.
- Phase 5 bytes moved is a sector model (distinct 32 B sectors per warp across own rows, cell ranges, cell lists, gathered pos/vel), i.e. L1-miss traffic to L2 assuming a warp's working set stays in L1. The crowd fits in the T4's 4 MB L2, so DRAM traffic is not what ordering changes. Achieved bandwidth = modelled bytes / kernel time.
- Phase 5 modelled time (simulator only, labelled `source=model`): max(issued / (40 SM x 4 SMSP x 0.5 IPC x 1.59 GHz), sectors x 32 B / 1 TB/s) + 4 us launch. It is memory-bound at sparse/mixed and issue-bound at dense, which is what makes the best w switch. Both constants are assumptions; the T4 replaces the whole column with CUDA-event medians and the policy recalibrates from the CSV.
- Phase 5 key family: the first version tried (`[coarse Morton][state][agent id]`) makes w=0 spatially blind; there w=0 was dominated at dense and w=1 nowhere, and the front was monotone (dense: w=0.4 418 B / 0.720, w=0.5 309 / 0.714, w=1 197 / 0.688). Kept as the `blind` reference only; the three-level key is the one reported because Morton inside a state group is free and strictly better.
- Phase 5 densities are tiled: the N=2000 simulator snapshot is replicated k x k (agents shuffled so the id tie-break carries no spatial information). 2000 agents is 63 warps, far too few to occupy 40 SMs, so per-w differences at N=2000 were within launch overhead in the model and would be latency-bound on the T4.
- The tier field in the key is the previous frame's tier (invariant 5). The study takes it from the phase 1 threshold assigner because the allocator needs telemetry costs; the hook for the allocated condition is the `assign` readback in `CudaAllocator.allocate`, and the key is agnostic to the source.

- Phase 6 scoring definition: the phase 3 table quality is agent-independent, so a GEMM needs a per-agent utility. The retained-energy profile phi_i = z_i^2 / |z_i|^2 makes behaviour and animation quality the fraction of the agent's own latent energy the tier keeps (linear in phi, hence a GEMM); nav and geo stay table constants (kappa_c). For a flat profile the structure matches the table, but the values differ (energy share k/d vs 1 - nMSE). Whether the allocator adopts the per-agent utility is a phase 7/8 decision; phase 6 compares INT8 against FP64 on the same utility.
- Phase 6 deviations from the confirmed derivation, all refinements of the same expansion: (1) the constant feature moved out of the GEMM into the epilogue, because a constant 1 set every row scale to 1/127 while energy shares are well below 1 (provable fraction at d = 16, lambda = 8.7 went from 0.19 to 0.54 at N = 300); the fp32 rounding count rises to 10u and the fp64 reference term to 5 2^-53. (2) Column scale max/126 instead of max/127 so the basis entries {0, 1/4, 1/2} quantise exactly (fbar_c = 0), and measured per-row residual caps ebar_i instead of Delta_i/2. (3) A pairwise interval on the score difference against the INT8 winner, eps_i(c, c*) = ebar_i |b_c - b_c*|_1 (+ the fbar terms, zero here), which is zero for rows sharing the winner's behaviour and animation tiers; it is the default and lifts the provable fraction from 0.36-0.89 to 0.94-0.99 at lambda > 0. The per-candidate interval remains available (`pairwise=False`) and is reported alongside.
- Phase 6 GEMM backend: Numba-CUDA has no WMMA/mma intrinsic, so the tensor-core path is `torch._int_mm` (cuBLASLt IMMA on sm_75), with K padded to 32 and m to a multiple of 8. Torch was already a dependency. The NumPy INT32 matmul is the oracle; on the T4 `gemm_bitexact` in the CSV must be True for every row since both are exact integer arithmetic.
- Reference and re-rank both use one njit sequential-order fp64 dot product, so the re-rank reproduces the reference's rounding exactly; a BLAS matmul could differ in the last bit and flip a knife-edge tie.

- Phase 7 KL measure: KL(cond || ref) at the fine (64-region) level, evaluated at realised states with fitted kernels, summed per agent since its last reconciliation (parity) or since t = 0 (baseline). At tier 3 the surrogate's fine-level kernel is the **sticky lift** (hold r while R is unchanged, draw r' ~ pi_ref(r' | R', ctx) on a region change); the memoryless lift proposed before implementation resampled the fine state every frame and charged the one-shot information loss H(r | R) every frame (3 nats/frame), so it was replaced. Frozen agents are charged -log P_ref(r | r), ticked-every-k agents KL(P_ref^k || P_ref) on tick frames and the frozen term on hold frames.
- Phase 7 per-frame rates are comparable between the surrogate and a frozen agent (walking: 0.010-0.011 vs 0.011 nats/frame; near_goal/chokepoint 0.05-0.06 vs 0.02). At hazard 1/90 the reference barely moves per frame, so "stay" is not surprising; the surrogate pays for region changes it makes. What separates the conditions in (a) is the forced restoration, not a lower rate; what separates them in state law is the region occupancy, which the surrogate matches by construction (MH) and a frozen agent does not.
- Phase 7 ledger: accrues the measured per-context surrogate rate e_rate[ctx] (agent-dependent), while the table's behaviour-tier-3 error rate is the worst rate over contexts with frequency > 1%, so the feasibility mask is conservative. Tiers 0-2 have rate 0 (they run the reference process; truncated decode is a quality loss, not a state divergence). Navigation error is zeroed in the phase 7 table because navigation tiers do not execute; the phase 3 placeholder remains in `alloc/config.py` untouched. Measured KL exceeds the ledger by up to 1.8x at the max because the ledger uses the context mean while the measured increment is per (ctx, region); p95 sits at the cap.
- Phase 7 budget: only the behaviour axis executes, so only its measured cost (plus the core) enters the budget; the non-executing axes cost 0 in this experiment (with the phase 3 stand-in geometry cost of 250 us the 6 us behaviour saving would never be chosen). Budget is expressed as floor + fraction of the allocatable range.
- Phase 7 baseline tick semantics (resolves the earlier open question): MassLOD sim tiers HIGH/MED/LOW tick the process and motion every 1/3/10 frames with accumulated dt (k process steps per tick, so the tick-time law is P^k); OFF is frozen. No extrapolation. No core, arrivals from fine position.
- Phase 7 core owns egress exactly: arrival is declared from s >= L, respawn positions and exits come from the world rng in completion order, and nothing in the core reads fine state, so under parity egress is byte-identical across camera paths (the tolerance in (b) is only a ceiling on how far the visible position can lag: BAND). The core's chokepoint capacity kappa (corridor door, 0.215 agents/frame) and the context-mean speed scale mbar come from a free full-fidelity calibration run without the core; the reference condition is full fidelity **with** the core.
- Phase 7 corridor route passes through the door centre (30, 5) so the core never crosses the wall; the chokepoint arc-length is taken at x = 29.5 on the first segment.

- Phase 8 conditions: `reference`, `baseline`, `parity`, `parity_nocap` (invariant 3 ablation, cap = 1e9 nats), `parity_authored` (invariant 2 ablation: quality = hand weights (0.4, 0.2, 0.2, 0.2) on authored ramps (1, 0.75, 0.5, 0); costs and rates unchanged). Grid counts 100/200/500/1000/2000/5000, `--frames 3000` below 2000 agents and `--frames-big 600` at or above. Calibration reused from the phase 7 N=200 cache per scene (surrogate kernels, kappa and per-agent cost are N-independent by construction; the sweep does not recalibrate per N).
- Phase 8 port numerics: fp32 `precise` scores plus integer-tick costs; the port's oracle is a Burst fp32 job with the same statement order, not the Python fp64 oracle. Fill capped at 8 dispatches, evaluations at 40 with `ForceFinish` returning the feasible bracket end. Ledger stays on the CPU; headroom sent to the GPU carries a margin of `L_max * e_max` for the readback latency.
- Phase 8 figures: Python frame times are prototype numbers; figure 3 picks its target from {33.3, 100, 333} ms for the prototype and uses 16.7 ms only for the engine CSV with the same schema.

## OPEN QUESTIONS
- Phase 8, **settled and worse than predicted**: `parity_authored` was expected to coincide with `parity` in KL but to separate in tier mix. It does **not** separate anywhere. Across all 114 cells the two conditions differ only in frame-timing fields; every KL, ledger, restoration, band, egress and tier field is byte-identical. Cause: tier mix under every parity condition is exactly `0.25 / 0 / 0 / 0.75` and tiers 1-2 are selected in **zero** parity cells (they appear only in 9 baseline cells, via the MassLOD bands). Tiers 0-2 cost within 0.2 us and carry rate 0, so tier 0 dominates 1-2 on quality at equal cost and the allocator's choice is binary, live-or-surrogate. Reweighting the quality column cannot change a decision with no alternatives. **The invariant-2 ablation therefore produces no signal at all and cannot support a claim either way as configured.** Options: (i) drop it, and say in the caption that invariant 2 is not separable in this telemetry; (ii) give tiers 1/2 real measured decode work at k = 8 / 4, recalibrate, re-run the three parity conditions. Figure 1 currently draws it dashed so it does not hide the parity line.
- Phase 8, **figure 3 is not publishable from this sweep**: `ft_low1_ms` (the 1% low, the number `figures/SPEC.md` says to quote) is dominated by machine noise, not by the system. `parity` and `parity_authored` make byte-identical tier decisions yet their 1% lows differ by up to 84% (plaza N=500: 14.56 vs 89.65 ms; corridor N=2000: 755.8 vs 519.4). The sweep ran for hours on a contended laptop, and the slowest-1% statistic picks up OS scheduling, not allocator behaviour. `ft_mean_ms` is far steadier (same pair within 6% at most counts). Either re-run the timing cells on a quiet machine, or quote the mean for the prototype figure and reserve the 1% low for the engine CSV where it means something.
- Phase 8: at T* = 33.3 ms the `reference` condition sustains **more** agents than `parity` in plaza (923 vs 775) and corridor (987 vs 380); parity wins only in hub (891 vs 845). The spec's check warns rather than fails here, correctly: the serial allocator is 11-29% of the parity frame at N=5000 (corridor 0.286) while the behaviour axis only saves ~6 us/agent, and the frame is dominated by O(N^2) separation that no condition changes. As it stands figure 3 does not support "PARITY sustains more agents"; that claim needs either the threaded/GPU allocator, real per-tier costs on the other three axes, or a cheaper neighbour structure.
- Phase 8: an invariant-4 ablation (`parity_nocore`: allocator + ledger with fine-authoritative arrivals) would isolate the egress guarantee in figure 2 but needs `Run` to support parity without the core; not added.
- Phase 8 sweep estimate on this M3 from the phase 7 rate (3.2 ms/frame at N=200 parity, separation O(N^2)): about 2-3 h for the 90-cell grid, plus a few minutes for `--cam-sweep`. The serial allocator is 30-50% of the parity frame at N=5000; `--allocator threaded` is oracle-identical and the CSV records which ran.
- Phase 8: `--frames 3000` at N=200 shows the baseline slope over 100 s; the phase 7 CSVs remain the 600 s source for figure 1's fallback.
- Phase 7: the behaviour reference is synthetic (jump process over corpus latents with a hand-set hazard and a context-compat boost), like the phase 2 targets. Rates and caps scale with the hazard; a real behaviour model would change the numbers, not the mechanism.
- Phase 7: measured KL max exceeds the ledger cap by up to 1.8x. Options: accrue the per-(ctx, region) rate directly (then ledger == measured by construction, weaker as evidence), or size the cap from the calibration's per-region max. Not done.
- Phase 7: band overshoot to 2.25 m comes from the scene wall/door clamps applied after `Core.bind`; binding after the clamp would make it exact but may push agents into walls.
- Phase 7: tiers 1-2 (latent8/latent4) carry rate 0 and cost the same as tier 0 in this telemetry, so the allocator uses them only through the quality term; nothing in phase 7 exercises them. Their divergence, if any, is in trajectory (speed-scale error), bounded by BAND.
- Phase 6, **settled on hardware, and the tensor-core framing does not survive it**. INT8 IMMA over fp32 is only **1.15-1.47x** — 1.27-1.37x at N=2000 and 1.41-1.47x at N=50000. Raising N from 2000 to 50000 barely moved it, so the earlier "needs N >= 50k to mean anything" explanation was wrong: the operation is not launch-bound, it is **output-bandwidth-bound**. At N=50k, m=184 the fp32 output alone is 50000 x 184 x 4 B = 36.8 MB, about 115 us at the T4's ~320 GB/s against a measured 274 us, while the arithmetic is only ~0.59 GFLOP against a 130 TOPS INT8 peak (~1.6% of peak). INT8 shrinks the inputs, not the output, so it cannot buy much here. Correctness is untouched and strong (bit-exact, 0.94-0.99 provable); the honest claim is "INT8 scoring is exact and certifiable", not "tensor cores make scoring fast".
- INT8 row resolution is set by the dominant first latent dim. A per-row two-scale split (head dim separately) or INT8 on log-energy would tighten the intervals; not done, since the pairwise interval already certifies 94-99% at lambda > 0.
- Phase 5, **settled on hardware, and it reverses the modelled conclusion**. Measured CUDA-event time per density at N=50k (us): sparse w=0 **513.7** vs w=1 845.0; mixed w=0 **940.8** vs w=1 1077.2 (blind 937.0, a 0.4% tie inside noise); dense w=0.1 **2453.5**, w=0 2565.0, w=1 2723.1. The model had predicted w=1 best at sparse/mixed and w=0 at dense; measurement says w=0 or near-0 everywhere. So the modelled "best w" column in phase 5 DONE is wrong and must not be quoted.
  - The phase 5 time model is off by roughly **100x in absolute terms** (dense w=0: 2565 us measured vs 16.98 us modelled; sparse 513.7 vs 12.58). Both of its constants were assumptions and at least one is badly wrong — 1 TB/s is A100-class, the T4 has ~320 GB/s. Bytes and WEE, which are counted rather than assumed, survive intact; only the time column dies.
  - Pareto criterion (a) is arguably now **met** in measured time: on the held-out sweep the best fixed w is 0.3 (mixed 16k), 0.2 (mixed/sparse 32k) and 0.1 (sparse 16k, dense 32k), so intermediate w beats *both* extremes at several points and neither extreme is universally optimal. This is the outcome the criterion was written for, and it only appears with real timings.
  - Adaptive criterion (b) now **FAILS** on held-out data: 5 of 6 density/size groups are worse than the hindsight-best fixed w, by 4-18% (`python -m order.adaptive`). It passes on calibration trivially. Cause: the policy's features are log1p(rho) and geff with no N term, and it only ever selects from {0.0, 0.1} because those won at the N=50k calibration size; but the optimum moves to 0.2-0.3 at 16k-32k, where the grid does not saturate the SMs. Fix is to add an occupancy/N feature and recalibrate across sizes, not just densities.
- Behaviour classes 2 and 3 (arriving, idle) are almost empty in these scenes: agents walk until arrival and are teleported. geff is 3 at sparse/mixed, so the coherence side is mostly the three tiers.
- Should MassLOD sim tiers throttle tick rate or freeze agents in the baseline? Currently they do not. This decides how "behavioural error" is measured against the baseline in phase 3.
- At N=2000 the sim histogram sits on the caps (80/400/1200/320) in the plaza. Cap sizes are placeholders; tune before treating the baseline as a fair opponent.
- Nested-dropout training makes the dimension ordering hold by construction. The plain AE, which is the un-engineered evidence, is also monotone on the mean curve but not on every seed (3 of 20 seed/head curves fail). Both rest on synthetic targets (see DECISIONS).
- Stray directory in repo root with a multi-line garbled name (from a failed setup script paste): **removed** (2026-09-24). It was not empty and not untracked as recorded here — it held one file and had been committed since `9b31928` (phase 1), so it was public on GitHub. `git rm -r --cached` plus a working-tree delete.

- Navigation and geometry per-axis fidelities in `alloc/config.py` are authored placeholders (1/0.9/0.6/0.3 and 1/0.75/0.5/0.25) and so is the navigation error rate. They are not in the latent, so invariant 2 covers only behaviour and animation. Replace with measured trajectory deviation (nav) and screen-space geometric error (geometry) once tiers execute.
- Telemetry times stand-in numpy kernels, not the simulator (phase 1 records tiers without executing tiered work). RLS fits genuine measured time, but the cost figures are not the crowd's. Navigation costs are unidentifiable under geometry noise at N=200; expect the same on the T4 unless nav work is real.
- Budget means predicted cost under the RLS model. `resid_var` is tracked; subtracting a k-sigma safety margin from the budget is not yet done.

- Nothing in phase 4 has executed on a GPU. On the T4: `pytest -q tests/test_parallel.py -k cuda` (kernels compile, libdevice path, constant memory from closure arrays, last-block pattern under real scheduling), `cd alloc/openacc && make acc` then `-k openacc`, then `python -m bench.speedup --sizes 1000 10000 100000` with CUDA-event timing if the perf_counter + synchronize numbers look launch-bound. `occupancy_report(CudaAllocator(table))` for the measured regs/thread.
- OpenACC with nvc: `#pragma acc update self(bj[besti:1], abuf[off+besti:1])` inside the fill and the `present(...)` subarray lookups have only been compiled as plain C. The `reduction(max:bestr)` with an `if` update is legal but check `-Minfo=accel` output.
- CUDA float-cost totals are summed in a different order from the oracle (see DECISIONS); if the T4 shows a mismatch on float costs at a knife edge, quantise costs to ticks inside `prepare()` for all implementations including the serial.

- The "dual-budget **joint**" framing is now measured, twice, and does not hold on quality: two different two-stage strawmen reach the joint solver's exact allocation. Decide which claim the writeup makes. The defensible ones are (a) the error cap is discharged *exactly* by the per-agent feasibility mask plus the ledger's forced restoration (invariant 3, which the demo shows as a sawtooth), and (b) pricing time by a single warm-started multiplier costs 20-400x less allocator time than resolving the budgets in sequence at identical quality. The indefensible one is "the joint solve allocates better".
- `test_sequential_utility_never_above_joint` asserts sequential <= joint. With the fill enabled that holds everywhere measured; with the fill disabled maximal-first beats joint by up to 0.22%. The assertion is therefore a statement about the *filled* allocator, not about the relaxation. Leave it, or restate it as equality.
